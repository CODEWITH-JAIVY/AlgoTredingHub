| Authentication | Redis unavailable, null counter, interrupted first increment, missing TTL, TTL lookup failure, or disappeared counter | Auth throttle repairs a counter without expiry or fails closed with 503; no request proceeds without a valid 15-minute window | Covered by unit tests; live Redis behavior remains unverified |

| Orders | Duplicate client order ID, same payload | Return original order | Covered |
| Orders | Duplicate client order ID, changed payload | 409 conflict | Covered |
| Orders | Simultaneous user orders at the open-order limit | Risk-policy row lock serializes risk reservation and order persistence | H2 integration test confirms only one order is accepted at a limit of one; PostgreSQL concurrency verification pending |
| Orders / discipline | Concurrent entries at the daily cap, duplicate idempotency retry, or accepted order cancelled later | Daily risk-state row is locked for check and increment in the order transaction; an identical retry returns the original order without consuming another entry; accepted entries remain counted after cancellation | H2 concurrency test confirms one accepted entry at a cap of one; unit/API tests cover idempotent retry, broker rejection, and no refund after cancellation; PostgreSQL lock behavior remains pending |
| Orders / discipline | First minutes after open, configured cutoff, weekend, full-day exchange holiday, or session boundary | Backend checks the IST NSE/BSE cash and equity-derivatives demo calendar, opening delay, and exclusive cutoff on each new order; unsupported calendar dates fail closed; cancel and kill-switch operations remain available outside order-entry hours | Implemented for verified coverage from 2025-11-05 through 2026-12-31; special sessions, early closes, halts, and instrument-specific exceptions are absent, so this remains mock-only |
| Orders / discipline | User tightens or relaxes entry count or time window during the day | Lower daily cap, earlier cutoff, and longer opening delay take effect immediately; relaxing values are staged for the next demo trading date | Implemented in policy state; PostgreSQL migration/API verification pending |
| Orders / discipline | Tighter opening delay overlaps with a cutoff while the corresponding relaxation is staged | The combined active window may temporarily be empty; the backend's independent opening and cutoff checks then reject every new order, and the policy screen displays the no-entry state | Implemented fail-closed; check the pending date before expecting entries to resume |
| Orders / discipline | Rejected broker request, cancelled accepted order, or retries after accepted submission | Explicit `REJECTED` results do not consume the daily counter; other returned states are conservatively counted; retries with the same key do not increment; later cancellation does not refund the entry | Mock adapter returns `OPEN`; terminal broker semantics remain unverified |
| Discipline | Loss streak or daily realized-loss threshold without recorded fills | Do not derive losses from open orders, manual journal values, or paper replay; loss-based cooldown/lock remains unavailable until a trusted fill and P&L lifecycle exists | Explicitly deferred; do not present as implemented |
| Pre-trade checks | User reviews an order while live-market, event, or authoritative P&L inputs are missing | Order review explicitly discloses that zone freshness, trend agreement, risk:reward, event risk, loss cooldown, and daily-loss lock are not evaluated; only available mock limits/time gates are enforced by the backend | Bilingual warning implemented; these missing checks still block any live-readiness claim |
| Orders / kill switch | Accepted mock order is open when the user activates the kill switch, then tries another order or deactivates the switch | Kill switch attempts cancellation, reports confirmed and unresolved counts, continues blocking submissions while active, and does not restore previously cancelled orders on deactivation | Covered by AuthLifecycleIntegrationTest HTTP flow on H2; Postgres runtime and browser visual flow remain pending |
| Orders | Network ambiguity after broker submit | Only mock adapter is called; no external side effect | Live adapter later needs broker reconciliation before retry |
| Broker safety | Accidental Zerodha or live-profile activation | Zerodha boundary reports no live execution and throws on place/cancel; mock adapter is excluded from the `live` profile; order service requires the mock provider | Direct adapter safety tests pass; independent release/deployment review remains a future gate |
| Orders | Invalid lot size / tick / price | Reject before mock adapter call | Covered |
| Orders | Missing or contradictory order-type prices | Validate order fields before price calculations and return the specific stable rejection code | Covered by risk service tests |
| Orders | Missing or wrong-side protective stop | Reject before mock adapter call | Covered |
| Orders | Per-trade risk, total daily risk, open count | Check stop risk, reserved open risk, daily state, max count | Covered for mock orders; no fills/P&L yet |
| Risk policy | User increases a risk limit during a session or edits a pending change | Stricter changes take effect immediately; relaxed fields are persisted as a pending schedule for the next supported demo session; current values remain enforced until then; returning a field to its current value cancels that relaxation | Unit/controller tests cover mixed changes, cancellation, holiday/weekend skipping, unsupported coverage, and order enforcement; special sessions and halts remain absent, and the calendar cannot gate live orders |
| Risk | Daily-state rollover or future-dated session | Reset a prior IST session date; fail closed if stored date is ahead of the current IST date | Covered by risk service tests |
| Orders | Untrusted client price | Use stored synthetic instrument data for market order reference | Covered only in mock mode |
| Kill switch | Duplicate activation | Idempotently remains active and reattempts cancellation of visible open mock orders | Covered |

| Kill switch | Deactivate while orders remain open, partially filled, or unknown | Keep the kill switch active, audit the blocked attempt, and return `409 KILL_SWITCH_UNRESOLVED_ORDERS`; deactivation is allowed only after all unresolved orders are resolved | Controller unit and H2 HTTP integration tests verify active state, stable conflict code, and independent blocked-attempt audit; PostgreSQL-backed runtime verification remains pending |
| Kill switch | Process restart | State is stored in PostgreSQL and blocks new orders after restart | Compose-backed restart verification pending; Docker/WSL engine unavailable |
| Market data | Stale, missing, duplicate, out-of-order, or post-finalization ticks | No provider is enabled until source rights are confirmed; Phase 2 deduplicates event keys and records `RECEIVED` → `BUFFERED` → `FINALIZED` or `RECONCILIATION_REQUIRED`; it bounds reordering, persists gaps, and flags synthetic samples | Focused unit and H2 migration tests pass; startup recovery restores the finalized watermark, replays only recent recoverable same-master receipts, and records stale-master or rejected ticks for reconciliation; PostgreSQL recovery remains unverified |
| Market data | Process stops after a receipt is claimed but before candle acceptance/finalization | V9 backfills old receipts as unknown; recent `RECEIVED`/`BUFFERED` receipts are replayed safely after restart, while expired or ambiguous outcomes require reconciliation instead of silent history changes | Ingestion, recovery, and V9 migration tests pass; PostgreSQL transaction/restart verification remains pending |
| Market data | Exchange holidays, special sessions, auctions, early closes, and halts | Synthetic calendar includes verified full-day holidays from 2025-11-05 through 2026-12-31; unsupported dates return `MARKET_CALENDAR_UNAVAILABLE`; analysis fails closed when its lookback crosses the unmodeled 2026-11-08 Muhurat session; other special sessions/halts remain unsupported | Maintain coverage from official exchange notices and authoritative real-time status before production |

| Market data | Redis/Postgres outage during tick stream | No live tick stream enabled; candle writes fail closed and reconnect recovery is provider-driven | Unit coverage only; Docker engine unavailable for database integration |
