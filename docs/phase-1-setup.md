# Phase 1 local setup

## Prerequisites

- 64-bit Windows, macOS, or Linux.
- Java 21 for direct Maven builds. The Maven Wrapper downloads Maven, not Java.
- Docker Desktop/Engine with Compose v2 for the local PostgreSQL and Redis services.

## Start local services

From the repository root in PowerShell:

```powershell
.\scripts\setup-local.ps1
docker compose --env-file .env -f infra/docker-compose.yml up --build
```

The setup script creates `.env` when missing, or fills only blank and placeholder settings in an existing file. Existing non-empty values are preserved. Keep `.env` private; it is ignored by Git. Local service ports bind to `127.0.0.1` only.

Health endpoint: `http://localhost:8080/actuator/health`

## Run tests

```powershell
cd services/backend
.\mvnw.cmd test
```

The test suite does not contact a broker. The test Spring profile uses an in-memory H2 database and a test-only JWT key; it includes a persisted auth-lifecycle integration test as well as unit tests.

Risk-policy changes are enforced by the backend. Tighter values apply immediately. A less restrictive value is returned in `pending` and becomes active at the next supported session; until then, current limits remain active. The versioned demo calendar models verified full-day holidays from 2025-11-05 through 2026-12-31 and fails closed outside its coverage. It does not model special sessions, early closes, or halts and must not be used to enable a live order path. See [market-calendar.md](market-calendar.md).

## Demo flow

All examples use placeholder credentials and synthetic data. Do not reuse a real password.

1. `POST /api/v1/auth/signup` with JSON `{"email":"demo@example.test","password":"Example-Only-Password-92"}`.
2. Use the returned short-lived access token as `Authorization: Bearer <token>`.
3. `GET /api/v1/market/instruments` to retrieve synthetic instrument IDs.
4. `POST /api/v1/orders` with a unique `clientOrderId`, one returned `instrumentId`, a valid lot multiple, and a protective stop. A response with `mode: MOCK` is only a simulated acknowledgement.
5. `GET /api/v1/orders`; cancel via `POST /api/v1/orders/{id}/cancel`.
6. Activate/deactivate account controls with `PUT /api/v1/risk/kill-switch` and `{"active":true,"reason":"demo"}`.

Every quote identifies `source: SYNTHETIC_DEMO` and `synthetic: true`. No live market data, real fills, holdings, or P&L are represented.

## Configuration

Only `.env.example` is committed. `JWT_SECRET_BASE64` must decode to at least 32 random bytes. The application fails at startup if it is missing or too short. Database and Redis passwords are local random values generated by the setup script. Production deployment needs a managed secret store, TLS, key rotation, backups, monitoring, and a reviewed network/security plan; none is configured by this local compose file.
